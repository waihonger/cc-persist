Design (approved in chat by WH 13:09 26 Sep, pasted verbatim):
- Claude Code (CLI 2.1.283) writes one JSON file per live interactive session at `<CLAUDE_CONFIG_DIR or ~/.claude>/sessions/<pid>.json` with fields pid, sessionId, cwd, name, nameSource, status (busy|idle|waiting), kind (interactive|background), updatedAt; it deletes the file when the session exits and rewrites it on /rename and on status change. `claude agents --json` (0.24 s for 132 rows on this machine) is the documented read of the same registry (fields pid, sessionId, cwd, name, status, kind).
- One `fs.watch` on that sessions directory replaces the signal dir watch and the 10 s poll. Rows that come back "retry" (terminal processId not yet resolvable) are retried on a short timer, 3 attempts, 2 s apart, then dropped until the next event.
- Read the registry by running `claude agents --json` (documented surface); if the command is missing or fails, fall back to parsing the files in the sessions directory directly (same fields). Never write to that directory.

- New setting `cc-persist.notifications` (boolean, default false). When true: for a TRACKED terminal that is not `vscode.window.activeTerminal`, a registry row for its claude pid moving from status busy to idle shows `vscode.window.showInformationMessage("<name or index>: done", "Show")` whose "Show" focuses that terminal; busy to waiting shows a `showWarningMessage("<name>: needs input", "Show")`.
